Цифровой архив театра

1. Описание проекта

Цифровой архив театра — веб-приложение для хранения и управления информацией о постановках, артистах, гастролях, фестивалях, конкурсах, документах и материалах театра.

2. Стек технологий

- Python 3.12
- Flask — веб-фреймворк
- SQLAlchemy (Flask-SQLAlchemy) — работа с базой данных
- SQLite — база данных
- Bootstrap — вёрстка интерфейса
- Jinja2 — шаблонизатор

3. Установка локально

3.1. Клонирование репозитория

```bash
git clone <URL репозитория>
cd theater_archive
```

3.2. Создание виртуального окружения

```bash
python -m venv venv
```

3.3. Активация виртуального окружения

Windows:
```bash
venv\Scripts\activate
```

Linux/macOS:
```bash
source venv/bin/activate
```

3.4. Установка зависимостей

```bash
pip install -r requirements.txt
```

3.5. Настройка переменных окружения

Скопируйте файл `.env.example` в `.env`:

```bash
copy .env.example .env      # Windows
cp .env.example .env        # Linux/macOS
```

Откройте `.env` и заполните:

- SECRET_KEY — ключ для подписи сессий Flask. Сгенерировать можно командой:
  ```bash
  python -c "import secrets; print(secrets.token_hex(32))"
  ```
  Если оставить пустым, ключ будет генерироваться заново при каждом запуске сервера, и все сессии пользователей будут сбрасываться при перезапуске.

- ADMIN_PASSWORD — пароль для встроенной учётной записи `admin`, создаваемой при первом запуске. Если оставить пустым, будет использован пароль по умолчанию `admin123`.

- DATABASE_PATH — полный путь к файлу SQLite.
- UPLOAD_FOLDER — полный путь к корню загруженных файлов.
- BACKUP_FOLDER — полный путь к каталогу резервных копий.

Пустые значения сохраняют прежнее поведение: база находится в
`instance/theater_archive.db`, файлы — в `uploads`, резервные копии — в `backups`
рядом с исходным кодом. Относительные пути разрешаются от каталога проекта, но
для сервера рекомендуется указывать полные пути.

3.6. Инициализация базы данных

```bash
python init_db.py
```

Эта команда применит миграции схемы и создаст базовые данные: роли пользователей и учётную запись администратора (если их ещё нет).

Для новой установки с вынесенными хранилищами вместо этой команды выполните
явную инициализацию (команда откажется перезаписывать существующую базу или
непустую папку файлов):

```powershell
python storage_tool.py initialize `
  --database C:\TheaterArchive\data\theater_archive.db `
  --uploads D:\TheaterArchive\uploads `
  --backups C:\TheaterArchive\backups
```

Для локальной проверки все три пути могут быть обычными папками на одном диске:

```powershell
python storage_tool.py initialize `
  --database C:\temp\theater-test\db\archive.db `
  --uploads C:\temp\theater-test\uploads `
  --backups C:\temp\theater-test\backups
```

3.7. Запуск приложения

```bash
python run.py
```

На Windows можно также воспользоваться файлом `start.bat` (двойной клик или запуск из консоли) — он сам вызовет `run.py`.

После запуска приложение будет доступно по адресу [http://localhost:5000](http://localhost:5000).

4. Перенос существующей базы и файлов

Перед переносом остановите веб-приложение. Не меняйте пути в `.env` вручную до
копирования. Из каталога проекта выполните:

```powershell
python storage_tool.py migrate `
  --database C:\TheaterArchive\data\theater_archive.db `
  --uploads D:\TheaterArchive\uploads `
  --backups C:\TheaterArchive\backups
```

Утилита делает проверенную резервную копию SQLite, копирует базу штатным SQLite
backup API, копирует дерево uploads с проверкой имён и размеров, сверяет все
`file_path` из базы и только после успешной проверки записывает новые абсолютные
пути в `.env`. Исходная база и исходный каталог uploads намеренно не удаляются:
удалять их следует вручную только после запуска и пользовательской проверки.

Полезные команды:

```powershell
python storage_tool.py status                 # пути, целостность БД и потерянные ссылки
python storage_tool.py backup                 # полная копия БД и uploads
python storage_tool.py backup --database-only # только согласованная копия SQLite
```

Полную резервную копию также рекомендуется выполнять при остановленном
веб-приложении, чтобы набор файлов не менялся во время копирования.

Если данные уже были перенесены другим способом, их можно подключить без
копирования командой `configure` с теми же тремя аргументами. Она также не
примет конфигурацию, если база повреждена или какой-либо файл по ссылке из БД
отсутствует. При опечатке в явном пути приложение завершит запуск с понятной
ошибкой и не создаст пустую базу или пустую папку вместо данных.

5. Структура проекта

```
theater_archive/
├── app.py            — инициализация приложения, регистрация blueprints, базовые роуты
├── models.py         — модели базы данных (SQLAlchemy)
├── config.py         — настройки приложения
├── utils.py          — вспомогательные функции (загрузка файлов и т.п.)
├── migrations.py     — миграции базы данных
├── init_db.py        — инициализация БД: применяет миграции и сеет базовые данные
├── storage.py        — разрешение путей и защита от пустого хранилища
├── storage_tool.py   — настройка, перенос, проверка и резервное копирование
├── run.py            — точка входа для запуска сервера
├── requirements.txt  — зависимости Python
├── routes/           — маршруты приложения (Flask blueprints)
├── templates/        — HTML-шаблоны (Jinja2)
├── static/           — статические файлы: CSS, JS, изображения
└── uploads/          — загружаемые пользователями файлы (в git не хранится)
```

6. Роли пользователей

- Администратор — полный доступ ко всем разделам, включая управление пользователями.
- Редактор архива — редактирование постановок, артистов и связанных данных.
- Завлит — доступ к редактированию либретто (помимо общих прав редактирования).
- Нотный библиотекарь — управление музыкальными материалами (клавиры, партитуры, фонограммы).
- Наблюдатель — только просмотр данных, без прав редактирования.

7. Журнал действий

Администратор может открыть пункт «Журнал действий» в разделе «Управление».
Таблица журнала создаётся автоматически при следующем запуске `python run.py`.
Журнал сохраняет дату и время, пользователя, действие и понятный снимок объекта
для успешного создания, изменения и удаления данных, а также для формирования
отчётов. Снимок названия и ID сохраняется независимо от исходного объекта, поэтому
запись об удалении остаётся читаемой. Пароли и другие секреты в журнал не передаются.

Отдельной серверной функции печати в приложении сейчас нет. Нажатие `Ctrl+P` —
локальное действие браузера, которое приложение не может достоверно отследить и
не записывает в журнал.
